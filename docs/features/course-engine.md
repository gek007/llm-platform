# Course engine

Spec: [course-engine-design](../superpowers/specs/2026-11-23-course-engine-design.md). The first half covers what learners see; "Admin generation" covers the admin flow. The `course-builder` eve agent (`agents/course-builder/`) does the research and writing; `COURSE_ENGINE_MODE=fake` swaps in a canned engine for local work without an agent.

## Chaptered courses

A course with rows in `chapters` is chaptered; lessons keep a global `order` and group via `lessons.chapterId`. Courses without chapters render as before (flat lesson list). Each chapter has at most one slide deck (`slideDecks`) and one test (`chapterTests`). The deck's schema, generation pipeline and viewer have their own page: [slide-decks.md](slide-decks.md).

- **Slides first.** A chapter opens with its slide deck; its lessons are the reading that follows. Every entry point follows that (`convex/lib/coursePath.ts` `chapterToStart`, shared by server and browser): **Start / Continue** on the course page and on dashboard cards (`enrollments.listMine` → `nextChapterSlug`) lead to the chapter page when the learner is about to start a chapter that has a deck (none of its lessons done yet), and to the next lesson otherwise (mid-chapter, a chapter without a deck, a course without chapters). **Next** on a chapter's last lesson opens the next chapter's slides.
- **Course page** (`/courses/[slug]`): when `chapters.length > 0` the outline is headed "Chapters" and grouped by chapter. Each group shows the chapter link, a **Slides** link as its first row (if a deck exists; it goes to the chapter page at the deck), the lessons and a "Chapter test" link.
- **Chapter page** (`/courses/[slug]/chapters/[chapterSlug]`, `src/components/chapter/chapter-view.tsx`): slide deck, lesson list, test card (question count, pass percent, best score, attempts used of max) and previous/next chapter links. Draft courses are admin-only.
- **Chapter sidebar** (`chapter-sidebar.tsx`): course → chapters → the current chapter's slides, lessons and test; a collapsible panel below `lg`.
- **Deck viewer** (`slide-deck.tsx`, see [slide-decks.md](slide-decks.md)): renders the deck's JSON with one component per layout, Mermaid diagrams, charts and tables; Prev/Next, arrows, Space and Esc (overview) on the focused deck, progress bar, speaker notes, light/dark, fullscreen; position resets per chapter. The deck is locked (`deck: null`) when the viewer cannot access the course content; signed-out visitors see a sign-in prompt, signed-in non-Pro viewers of a Pro course see an upgrade link. A chapter without a deck points to its lessons; an admin of a generated course sees a skeleton while it is being written and an error state (with "Regenerate chapter slides" or a link to the job) when it is missing.
- **Lesson page**: passes the course `language` to the markdown renderer and lists the lesson's sources ("Sources", external links) under the body. In a chaptered course its header names the chapter (link to the chapter page) with a "Chapter slides" link, and its sidebar is the same chapter-grouped outline as the course page, each chapter starting with its Slides link.

## Chapter tests

Page: `/courses/[slug]/chapters/[chapterSlug]/test` (`chapter-test.tsx`). Kinds: `single`, `multiple` (all-or-nothing), `true_false`. Defaults: pass at 70%, 3 attempts. The best attempt decides `passed`. `correct` and `explanation` are returned only after a submission. Submitting takes `{ testId, version, answers }`; if the test changed meanwhile the learner is told it was updated and no attempt is used. Editing a test bumps `version`; earlier passes still count.

## Completion

A course is complete when every lesson is complete and every chapter test is passed (`progress.courseCompletion`; `enrollments.listMine` carries `testsPassed`, `testCount`, `complete`). The dashboard card shows a "Complete" badge when `complete` is true.

## Right-to-left

Hebrew (`he`) is the only RTL language. Content containers (course description, chapter heading and summary, lesson list, slide deck, tests, lesson body) get `dir="rtl" lang="he"`; code blocks stay LTR; app chrome stays English.

## Seed course

`digital-safety-basics`: free, published, Hebrew, 2 chapters x 2 lessons (`chapter-1`, `chapter-2`), each with a 6-slide deck and a 4-question test (the 8-10 questions / 8-15 slides rules apply only to engine-generated content; these seeded decks are text-only and have no slide ids, like any deck saved before the deck schema). It is created by `npx convex run seed:run` and used by `e2e/chapters.spec.ts` (signed-out: two chapter groups, deck locked with a sign-in prompt).

Signed-in end-to-end flows are not covered yet (no Clerk testing tokens); unit and component tests cover the chapter view, outline, sources and course card.

## Admin generation

Admin-only pages (the admin layout gates them; Convex re-checks with `requireAdmin`).

- **Wizard** (`/admin/generate`, `src/components/generate/generate-form.tsx`): topic (required, 3 to 200 characters), language (English / עברית / Русский), level, length preset (short 3 x 2-3, medium 5 x 3, long 8 x 3-4; shown under the select), optional audience and notes, and resources: web URL, YouTube URL (embed-only), pasted text, PDF upload (20 MB, rejected client-side and again by `addResource`). **Generate** runs `createJob`, one `addResource` per resource (PDFs upload via `generateUploadUrl` first), then `POST /api/course-builder/start`, then opens the live view. The button disables while the request runs.
- **Live view** (`/admin/generate/[jobId]`, `job-live-view.tsx`): reactive over `generation.get`, `events` and `sources`. Stepper Research, Outline, Writing, Ready; activity feed; sources list; per-chapter cards while writing (latest event for that chapter).
- **Jobs list**: `/admin` shows all jobs (`generation.list`) under the courses table; "Generate with AI" opens the wizard.

### Statuses and controls

| Status | UI |
| ------ | -- |
| `queued` | Waiting; **Start** (normally the wizard already started it) |
| `researching` | Feed and sources only |
| `outline_ready` | Outline editor: rename, reorder, add/remove chapters (max 10) and subchapters (max 5), edit goals; **Save outline** (`updateOutline`) and **Approve and write** (saves unsaved edits, then `POST /approve`). Field values hold course-language content, so they use `dir="auto"` |
| `writing` | Chapter cards, feed |
| `ready` | **Open draft course** (`/admin/courses/<courseId>`) |
| `failed` | Error and **Retry phase** (`POST /resume`) |
| `researching` or `writing`, with `dispatchError` | Error and **Resume** (the engine could not be reached). A `dispatchError` left from an earlier phase is not shown; `markDispatched` clears it |

A 409 from a route (double click, or another tab acted first) shows "already <status>" and the reactive query refreshes the view; a 502 means dispatch failed and the job gets `dispatchError`. Before every dispatch the route records the command on the job (`generation.setPendingCommand` → `generationJobs.pendingCommand`; the route-driven transitions clear it first). **Resume** and **Retry phase** re-send exactly that command, so a regenerate whose dispatch failed is retried as that regenerate; only a job without a recorded command falls back to the status (`researching` → research, `writing` → write, `failed` → write with a course, else research).

### Engine API and modes

`POST /api/course-builder/{start|approve|regenerate|resume}` (`src/app/api/course-builder/[action]/route.ts`) re-checks the admin, runs the Convex transition (`startJob`, `approveOutline`, `requestRegenerate`) and dispatches the command to the engine. `COURSE_ENGINE_MODE=fake|live` (Next.js env, default `live`): `fake` runs a canned engine that calls the same `/engine/*` endpoints with the same validation, so the whole flow works without the agent or an Anthropic key. The agent (and the fake engine) write through the Convex HTTP surface `POST <CONVEX_SITE_URL>/engine/<op>` (`convex/http.ts`), authenticated with `Authorization: Bearer <COURSE_ENGINE_SECRET>` (constant-time check in `convex/lib/engineAuth.ts`; fails closed when unset). Ops live in `convex/engine.ts`: `getJob`, `getChapterContent` (read-only: one chapter's saved lesson bodies, capped at 12,000 characters each with `truncated`, plus its deck slide titles and test question prompts, never answers; scoped to the job's own course), `setResourceStatus`, `saveSources`, `saveOutline`, `reportProgress`, `saveSubchapter`, `saveDeck`, `saveTest`, `finishJob`, `failJob`.

### Live dispatch (course-builder agent)

In `live` mode `dispatch` calls `sendToAgent` (`src/lib/course-builder/eve-client.ts`): `POST <COURSE_BUILDER_URL>/v1/session {message}` for a new session, `POST .../v1/session/<id>` for a follow-up, where the message is `commandMessage(cmd)` and each request carries a fresh HS256 JWT (`iss: llm-platform`, `aud: course-builder`, `sub: course-builder-route`, 60 s expiry) signed with `COURSE_BUILDER_CHANNEL_SECRET`; eve treats it as a `service` principal. `start` always opens a new session; `approve`, `regenerate` and `resume` follow up on the job's stored `eveSessionId`. A follow-up answered 409 (session not active) or 500 (stranded after a plain `eve dev` restart) is re-sent as a new session and the route stores the new id; any other failure is thrown and recorded as `dispatchError` (the live view offers **Resume**). `COURSE_BUILDER_URL` defaults to `http://127.0.0.1:2001/eve`, the `npm run dev:course-builder` server.

The agent (`agents/course-builder/`) reads and writes only through `/engine/*` with `createEngineClient` / `engineFromEnv` (`CONVEX_SITE_URL`, else `NEXT_PUBLIC_CONVEX_SITE_URL`, else `NEXT_PUBLIC_CONVEX_URL` with `.convex.cloud` -> `.convex.site`; `COURSE_ENGINE_SECRET`); a failed op throws `EngineError` with the server's whole `"CODE: detail"` string. `getJob` returns `JobBrief` (`convex/lib/engineTypes.ts`).

### Research tools (course-builder agent)

The research phase runs on these tools in `agents/course-builder/agent/tools/`; each takes the command's `jobId` and answers `{ ok: false, message }` (the engine's `"CODE: detail"`) instead of throwing when the engine refuses a call:

- `get_job`: the `JobBrief`.
- `read_resource { jobId, resourceId }`: URL → readable text (HTML stripped, `<main>`/`<article>` preferred, truncated to 60 000 characters); PDF → the Convex storage file as base64, given to the model as a `toolOutputPart.file(..., { mediaType: "application/pdf" })` part, only within the model budgets in `lib/pdf.ts` (at most 100 pages, estimated from page objects incl. compressed object streams; 10 MB per PDF; 15 MB for all PDFs read in the job), otherwise `unreadable` with the reason ("the PDF has 142 pages; the model accepts up to 100"); pasted text → as is; all three are marked `read`. YouTube → `embed_only` with the oEmbed title and channel (the platform's "YouTube video" placeholder title is replaced with the real one); never a transcript. A failed fetch, a PDF over 20 MB (`PDF_MAX_BYTES`) or a non-PDF file marks the resource `unreadable` and logs the reason as a `source` progress event.
- `youtube_info { url }` → `{ videoId, title, channel }` (`lib/youtube.ts`; the oEmbed URL is built from the parsed video ID).
- `web_search` (eve built-in; the direct Anthropic model gets Anthropic's native search) and `web_fetch` (eve built-in: https only, every hop of up to 10 redirects SSRF-checked including at connect time, 5 MB cap), re-enabled because the agent sets `defaultTools: false`.
- `save_sources` (refuses any URL equal to or on the host of a job resource's `fileUrl`, or a Convex `/api/storage/` path: admin PDFs stay behind access-checked ```resource blocks and are never public sources), `save_outline` (checks the job's length preset before calling the engine: short = exactly 3 chapters of 2-3 subchapters, medium = 5 of 3, long = 8 of 3-4; caps 10/5), `report_progress` (`lib/report-progress.ts` `makeReportProgressTool`, shared with the chapter-writer).

**Fetch safety** (`lib/safe-fetch.ts`, used for pages, PDFs and oEmbed): https only on every hop; at most 3 redirects, each re-validated; destinations go through `guarded-fetch` (direct dependency, pinned): IP literals in any spelling (decimal, octal, hex, IPv4-mapped, NAT64, 6to4, Teredo) and resolved hostnames are refused when private, loopback, link-local (cloud metadata), CGNAT, ULA or reserved, `localhost`/`*.localhost`/`*.local` by name, and the address is re-checked inside the socket's DNS lookup (DNS rebinding); streamed byte caps (PDF 20 MB, text 5 MB, JSON 256 KB) abort past the cap; Content-Type must match and a PDF must start with `%PDF-`; the turn's abort signal and a per-kind timeout (PDF 90 s, page 30 s, oEmbed 15 s) bound the whole fetch, body included. Convex storage `fileUrl`s take the same path (public https, so they pass; caps still apply).

### Chapter writer (course-builder agent)

`agents/course-builder/agent/subagents/chapter-writer/` writes one chapter's lessons and test per run (`claude-opus-5-5`, `reasoning: "high"`, `defaultTools: false`, `tool: false`: only the write fan-out reaches it). Its message is `buildWriterBrief(job, chapterOrder)` (`lib/writer-brief.ts`): jobId, topic, language (with the localized True/False labels: en "True"/"False", he "נכון"/"לא נכון", ru "Верно"/"Неверно"), level, audience, notes, the chapter and each subchapter's title and goal (from the course rows: `getJob` returns each lesson's `summary`, which approval sets to the outline goal and which follows the admin's renames and reorders), every saved source as `[id] title — url — excerpt` (`getJob` returns the excerpt `save_sources` stored; the brief shows its first 1,500 characters; YouTube sources also get a ready ```youtube block), the job's pasted text under "Pasted material" (source material only, never a block), and the admin resources planned for this chapter (`resourceIds`, only in the frozen outline) as ready-to-paste blocks: PDFs and URLs as ```resource, YouTube as ```youtube. A planned resource goes to the lesson with exactly the same title as its outline subchapter; one whose outline subchapter matches no lesson is offered at chapter level ("planned for '<outline title>'") for the writer to place, never on a neighbour by position. Unreadable ones and other chapters' resources are left out, and storage URLs never appear. Writers cite `[n]` only for what a source's excerpt (or title) supports. Citation rule: `[n]` in a lesson body is the n-th id in that `save_subchapter` call's `sourceIds`. Tools `save_subchapter` and `save_test` (8-10 questions) pass their input straight to the engine and answer `{ ok: false, message }` with the engine's text ("Unknown reference: X", "INVALID: …"); the writer retries a failed save at most twice, then lists it in `problems`. It answers with `writerOutputSchema`: `{ chapterOrder, saved: { subchapters, test }, problems }`. It writes the lessons and the test only: the slide deck is built afterwards from the saved lessons.

### Deck writer (course-builder agent)

`agents/course-builder/agent/subagents/deck-writer/` writes one chapter's slide deck per run, as structured JSON (same model and effort, `defaultTools: false`, `tool: false`, **no tools**: it never saves anything itself). Its message is `buildDeckBrief(job, content, instruction?)` (`lib/deck-brief.ts`): the course, the whole outline with this chapter marked, a style guide shared by every chapter, the chapter's saved lessons from `getChapterContent`, source excerpts for quote slides (titles only, never URLs) and the rules (8-15 slides, `title` first, `summary` last, 40% of slides with a visual, diagrams as Mermaid code, at most 5 bullets under 12 words, notes of 2-4 sentences). The turn's `outputSchema` is the deck schema (`convex/lib/deck.ts`). `lib/generate-deck.ts` validates the answer, feeds problems back for at most 2 retries, checks every Mermaid diagram with `mermaid.parse` (`lib/mermaid-validate.ts`, behind the `validateDiagrams` step), re-asks only a slide whose diagram is invalid, falls back to bullets if it stays invalid, and saves through the `saveDeck` step; an engine refusal is fed back the same way. Details and the reasons: [slide-decks.md](slide-decks.md).

### Write phase and regenerate (course-builder agent)

The agent's phases follow the command it gets (every command starts with `get_job` and uses only the command's `jobId`). A job-level failure ends with **`fail_job { jobId, error }`** (engine `failJob`): the job turns `failed` with the real cause at once, so the live view shows it and offers **Retry phase** instead of waiting ~15-20 minutes for the watchdog's generic stall. `BAD_STATE` while the job is in the command's own phase → `fail_job`; the phase already done → stop; the job in an unrelated phase (for example `outline_ready` for a write) → job left as it is, with an `error` progress event first when that phase is `researching`, `outline_ready` or `writing` (`reportProgress` is accepted there; `outline_ready` logs without a status change, so the research phase can report its outline after `save_outline`).

| Command | What the agent does |
| ------- | ------------------- |
| `research` | Reads resources, searches, `save_sources`, `save_outline` (see Research tools); the job waits in `outline_ready` |
| `write` | `write_course` (every chapter, or only the incomplete ones on a repeated or resumed command, judged from `hasBody`/`hasDeck`/`hasTest`), then `finish_job`. Only an `INCOMPLETE` refusal from `finish_job` gets **one more** `write_course` for the chapters it names, then `finish_job` again; a second refusal, or any other refusal, → `fail_job` with the message |
| `regenerate` | `regenerate` with the command's `target` and `instruction`, then always `finish_job` (R6: the route moved the job `ready → writing`; finishing moves it back to `ready`, even if the rewrite reported a problem, since the earlier version of the item is still saved) |

- **`write_course { jobId, chapterOrders? }`** (`tools/write_course.ts`, a `defineWorkflowTool` with `execute`, so the turn waits for it): a `"use step"` `getJob`, then one `ctx.agent("chapter-writer").send(buildWriterBrief(job, n), { outputSchema: writerOutputSchema, signal: ctx.abortSignal })` per chapter, all in one `Promise.all` (`lib/write-chapters.ts`). Each writer is its own child session and runs to the end of its turn. When a chapter's writer has finished, the deck pipeline runs for that chapter (`runDeck`: a `deck-writer` session, see Deck writer), so a chapter holds one session at a time. A deck that could not be saved is a problem of that chapter ("Slide deck: …"), not a failed run: its lessons and test stay saved. A chapter whose lessons and test are saved and whose deck is the only gap (a repeated or resumed write) skips the chapter writer. A writer that throws, fails, is cancelled, returns no valid report or reports problems never stops the others: each run settles into a report or a failure, and each logs one `chapter` progress event ("Chapter 2 written: 3 subchapters, slide deck and test saved", "Chapter 2 is incomplete: test not saved; …", "Chapter 2 failed: …") through a step that never throws. It returns `{ ok: true, chapters: [{ chapterOrder, saved, problems }], failed: [{ chapterOrder, reason }] }`, where `failed` holds every chapter that still needs work (failed run, problems, deck/test not saved, fewer subchapters than planned). It refuses up front, without starting a writer, when the job isn't `writing` (or `failed`, which the engine resumes), has no course, or `chapterOrders` names a chapter that doesn't exist. **No concurrency cap:** at most `MAX_CHAPTERS` (10) writers run at once, under eve's 32-task limit; the spike verified 10-way parallel fan-out with trivial children only, so Anthropic rate limits for up to 10 simultaneous Opus writers (and multi-minute children) are not yet verified. If they bite, add a cap in `writeChapters`.
- **`finish_job { jobId }`** (`tools/finish_job.ts`): engine `finishJob` → `{ ok: true, status: "ready" }`. A refusal ("INCOMPLETE: Chapter 2: deck missing; Chapter 3: lesson "x" has no body") comes back as `{ ok: false, message, missing: [one line per gap], chapterOrders: [2, 3] }`, which is what the agent passes to the one retry of `write_course`. The parser (`missingFromRefusal`) reads a chapter number only at the start of a gap and runs a lesson gap to its closing `" has no body`, so a lesson title containing "; " or "Chapter 9:" neither splits a gap nor adds a chapter.
- **`regenerate { jobId, target, instruction }`** (`tools/regenerate.ts`, workflow tool): `chapter` → the same fan-out for that one chapter, with a "Regenerate the chapter" section carrying the instruction (this is also what a **Retry chapter** button would send; see Deviations); `deck` → the deck pipeline alone (`runDeck`), built from the saved lessons with the instruction and the replaced deck's slide titles in the deck brief; it answers `redone: false` with the reason when the deck could not be saved, and the saved deck stays as it was; `subchapter` / `test` → one chapter-writer run with the chapter's brief plus "Only redo <target>: <instruction>" (`lib/regenerate.ts`; an empty instruction becomes "write it again to a higher standard"), telling the writer to save only that item with its save tool, plus the chapter's **saved content** from engine `getChapterContent` (a `"use step"`): every saved lesson body (the target subchapter marked "saved version of the item you rewrite", its neighbours "do not rewrite: context only", a truncation note when capped), the deck's slide titles and the test's prompts. A regenerated test must be answerable from those bodies. The chapter writer's brief carries saved content only for these single-item regenerates. A refused `getChapterContent` returns `{ ok: false, message }` before any writer starts. It returns `{ ok: true, target, redone, saved, problems }` (`redone`: the writer saved the target) or `{ ok: false, message }`, and logs a `chapter` event either way. An unknown chapter or subchapter is refused before any writer starts.

**Eval** (`agents/course-builder/evals/tiny-course.eval.ts`, `npm run eval:course-builder`, run on demand: it calls the real model). `evals.config.ts` `setup` starts `evals/lib/fake-engine.ts`, an in-memory `/engine/*` server on 127.0.0.1 holding one approved 1-chapter, 2-subchapter English course in `writing` (one fixture source with an excerpt), and sets `CONVEX_SITE_URL` to it before eve starts the local agent server (eve's `.env.local` loader never overrides a variable already set). The fake speaks the real wire format and validates like the engine where cheap: job state (content only in `writing`), chapter/subchapter existence, text limits, decks against the real deck schema (`checkDeckDraft`, 8-15 slides), 8-10 questions with the real `validateQuestion`, unique question ids, `sourceIds` belonging to the job, and "no invented links" with the real `findUnknownRefs` / `findUnknownRefsInText`; `finishJob` lists the gaps like the real one. The eval sends a `write` command and asserts `get_job` → `write_course` → `finish_job`, both lessons saved with a body and a ```quiz block, an 8-15 slide deck (`title` first, `summary` last, with visuals), an 8-10 question test, the job `ready`, and a chapter progress event. A second eval, `dns-deck.eval.ts` (`npm run eval:course-builder -- dns-deck`), covers the deck pipeline alone: the fake server also holds a "How DNS works" job whose lessons and test are already saved (`evals/lib/dns-course.ts`), so a `write` command skips the chapter writer; it asserts that only `saveDeck` wrote, that the stored deck passes `deckSchema`, the 40% visual share (less any diagram that fell back) and a Mermaid diagram, and with `EVAL_DECK_OUT=<file>` writes the deck JSON (the sample in `src/components/chapter/samples/`). The course-builder channel has no `localDev()`, and `eve eval`'s local client sends no credentials, so `lib/channel-auth.ts` adds `localDev()` only when `EVE_EVALUATION=1` **and** `EVE_EVALUATION_RUN_ID` is non-empty (eve eval sets both for its own server; never set `EVE_EVALUATION` in `.env.local`; `localDev()` itself still requires a local development server and a loopback request).

### Watchdog

`convex/crons.ts` runs `engine.failStalledJobs` every 5 minutes; a `researching` or `writing` job with no update or event for 15 minutes becomes `failed` with the error "No progress for 15 minutes". A late write from the agent on such a job is accepted, the job returns to `writing` and an event is logged.

### Source integrity

`convex/lib/sourceScan.ts` parses lesson markdown the way the renderer does. Every http(s) link must be a source the engine saved (`saveSources`, from pages it read); unknown URLs, including raw URLs in slide and test text, are rejected with "Unknown reference: <ref>". ```youtube / ```resource blocks must reference saved resources. **Pasted text is source material only** (controller ruling): learners never see it. The writer brief lists it under "Pasted material" for the writers to draw on and never offers a block for it; `saveSubchapter` refuses a ```resource block that places a text resource and `saveOutline` refuses a text resource id in `resourceIds` ("INVALID: resource <id> is pasted text: source material only…"); it can't be cited as `[n]` either (sources must be http(s)). Engine saves are accepted only in `writing` (or `failed`, which resumes) and are refused with `BAD_STATE` "Course is published; unpublish it to let the engine write" once the course is published. Regenerating a published course is likewise refused ("Unpublish the course to regenerate"), so AI content never lands in a live course.

### Deviations from the spec

- **No separate Retry chapter button.** **Retry phase** on a failed job re-sends its command; a write rewrites only the chapters that are still incomplete. On a `ready` job, **Regenerate chapter** in the course editor covers rewriting one chapter.
- **Token usage is not recorded yet.** `generationJobs.usage` (`{ inputTokens?, outputTokens? }`) exists in the schema, but nothing writes it; the eval numbers above come from eve's `usage.recorded` facts.
- **Pasted text is source material only** (see Source integrity): the spec never shows pasted text to learners, so it is never placed in a lesson.

## Admin review (course editor)

`/admin/courses/[courseId]` shows the course details form (now with a **Language** select) and two tabs.

- **Content** (`ChaptersPanel`): one card per chapter with editable title and summary (`admin.updateChapter`), its lessons (links to the existing lesson editor), and buttons that open the **deck editor** and the **test editor**. A course with no chapters (hand-made) keeps the plain lessons list.
- **Deck editor** (`DeckEditor`, `admin.getDeck` / `updateDeck`): slide list with move up/down, delete and add; per-slide layout (all eight), title, the fields that layout uses (subtitle, bullets, two columns, quote and attribution, code language and source, the visual as JSON checked against the deck schema as you type), speaker notes, and a live preview with the shared `Slide` component (diagrams and charts included). 6 to 20 slides; switching layout drops fields the layout does not use on save; a generated slide keeps its `id`, `visual` and `code` through an edit. Hand edits follow `validateSlide`, not the generation rules (no 40% visual share, no title-first rule).
- **Test editor** (`TestEditor`, `admin.getTest` / `updateTest`): questions with kind, prompt, options, correct toggles and explanation, pass mark (1-100) and max attempts (1-20). It checks every question with the server's `validateQuestion`, so a `single` question with two correct answers cannot be saved. A notice states that saving changed question content creates a new version (earlier passes still count; pass mark and attempts alone do not bump it).
- **Results** (`ResultsTable`, `tests.resultsForCourse`): learners by chapter tests, each cell showing best score, passed or not, and attempts.
- Content fields use `dir="auto"` and the container follows the course language (`he` is RTL); the admin chrome stays English. Server errors (`INVALID: <detail>`) are shown to the admin as-is.

### Regenerate (admin)

Generated courses (those with a `generationJobId`) get a **Regenerate** button on each lesson, the deck, the test and the chapter. The dialog needs an instruction (1 to 500 characters) and posts `{ jobId, target, instruction }` to `/api/course-builder/regenerate` through the shared `postAction`. While the job is `writing` the panel shows "Regenerating…" with the latest job event and disables the buttons. If the job is `failed` (a regenerate the agent could not finish, or the watchdog), the panel shows "Regeneration failed: <error>" with a link to `/admin/generate/<jobId>`, where **Retry phase** lives. Regenerate on a job whose course was deleted is `BAD_STATE`. A published course is refused: the route answers 409 with "Unpublish the course to regenerate" and the dialog shows it. Hand-made courses have no regenerate controls.

### API notes for Task 17

- **Agent:** `import { defineAgent } from "eve"; import { anthropic } from "eve/models/anthropic";` `defineAgent({ model: anthropic("claude-opus-5-5"), reasoning: "low" | "medium" | ..., defaultTools: false })`. Subagents: `agent/subagents/<name>/agent.ts` (+ `instructions.md`, own `tools/`), `defineAgent({ description /* required */, model, reasoning, defaultTools: false, tool: false /* hidden from the parent model, still reachable via ctx.agent */ })`. A subagent inherits nothing from the root.
- **Tool:** `import { defineTool, toolOutput, toolOutputPart } from "eve/tools";` `defineTool({ description, inputSchema: z.object({...}), async execute(input, ctx) {...}, toModelOutput(output) {...} })`. `ctx.abortSignal` aborts when the turn is cancelled; pass it to `fetch`.
- **PDF to the model:** return the base64 from `execute`, then `toModelOutput: (o) => toolOutput.content([toolOutputPart.text("..."), toolOutputPart.file(o.base64, { mediaType: "application/pdf", filename: "source.pdf" })])`. eve warns above 3 MiB, saves the file to the session sandbox and re-sends it on every later model call (cost). For big files use `toolOutputPart.fileUrl(httpsUrl, { mediaType })` (https only; the URL must stay readable for the whole session). Note the full `execute` output (including base64) is stored on `call.settled`; keep it small or drop the base64 there.
- **Workflow tool:** `defineWorkflowTool({ description, inputSchema, async execute(input, ctx) { "use workflow"; ... } })` from `eve/tools`. Side effects, clocks and app calls go in top-level `async function x() { "use step"; ... }`. Fan-out: `await Promise.all(items.map(async (it) => { const r = await ctx.agent("chapter-writer").send(msg, { outputSchema: zodSchema, signal: ctx.abortSignal }); return await r.result(); }))`; `result()` gives `{ status: "completed" | "failed" | "cancelled", data, reply, error? }`. `ctx.agent(name, { model })` overrides need an AI Gateway model id, so keep the model in the subagent's own `agent.ts`. Durable primitives come from `eve/workflow` (`sleep`, `FatalError`, `RetryableError`). A session runs at most 32 working tasks.
- **Built-in web tools:** with `defaultTools: false`, add `agent/tools/web_fetch.ts` with `export { default } from "eve/tools/web_fetch";` and `agent/tools/web_search.ts` with `import { webSearch } from "eve/tools/web_search"; export default webSearch({ provider: "native" });` (`provider` is required by the type but applies only to AI Gateway models; a direct Anthropic model always gets Anthropic's native search). Not exercised in the spike.
- **Channel:** `agent/channels/eve.ts`: `eveChannel({ auth: [jwtHmac({ algorithm: "HS256", issuer: "llm-platform", audiences: ["course-builder"], subjects: ["course-builder-route"], secret: process.env.COURSE_BUILDER_CHANNEL_SECRET! })] })` from `eve/channels/eve` and `eve/channels/auth`. `issuer` and `audiences` are required; the token must carry matching `iss`, `aud`, `sub`, `exp` (clock skew 30 s). No `localDev()`, so local calls need a token too.
- **HTTP (what `sendToAgent` does):** header `Authorization: Bearer <HS256 JWT>`, `Content-Type: application/json`.
  - New session + first turn: `POST <base>/eve/v1/session` with `{"message": "<text>"}` (optional `operationId` for retry-safe create) → **202** `{"ok":true,"sessionId":"wrun_...","deliveryId":"..."}`.
  - Follow-up: `POST <base>/eve/v1/session/<sessionId>` with `{"message": "<text>", "idempotencyKey"?: "..."}` → **202** with a new `deliveryId`. Unknown or ended session → **409** `session_not_active` (create a new session and store the new id). Unknown fields → 400.
  - Watch: `GET <base>/eve/v1/session/<sessionId>/stream` (NDJSON `{at, facts:[...]}`; `?follow=false` reads recorded history). Turn end is `turn.settled` (`outcome`), reply text is `content.completed` with `kind: "text"`.
  - Base URL: `http://127.0.0.1:2000` for `eve dev`; behind `withEve` in a workspace the agent mounts at `/eve/<name>/v1/*` (for example `/eve/course-builder/v1/session`). The typed alternative is `new Client({ baseUrl, auth: { bearer: () => sign() } })` from `eve/client`, then `client.sessions.create({ message })` / `client.sessions.attach(id).send(text)`.
- **Token usage:** yes, per model run. The stream has `usage.recorded` facts `{ kind: "model", owner: { runId } | { callId }, usage: { inputTokens, outputTokens, cacheReadTokens, cacheWriteTokens } }`; a workflow tool's children are rolled up into one record owned by the tool's `callId` (10 children: 5330 in / 490 out). No `costUsd` with the direct Anthropic provider. `limits.sessionUsage` can cap spend.

### Gotchas

- **`--resume` is required locally.** A new `eve dev` leaves old sessions dormant; the dev script for the course-builder should run `eve dev --agent course-builder --resume` so job sessions survive a restart. On Vercel Workflow sessions survive redeploys without this.
- **`eve dev` auto-installs `just-bash`.** On first start it ran `npm install --save-dev just-bash` (default sandbox; tool file parts are written to the sandbox), editing `package.json` and `package-lock.json`. Task 17 should add it on purpose and commit it.
- **Env and port:** `eve dev --agent <name>` from the repo root loads the root `.env.local` (both `ANTHROPIC_API_KEY` and `COURSE_BUILDER_CHANNEL_SECRET` were picked up). Default port 2000 (`--port` or `PORT` to change); with `--no-ui` wait for the `[DEV] ready at` line.
- **Bundling app code:** a workflow tool imported `commandMessage` / `parseCommand` from `../../../../src/lib/course-builder/commands` and called them in a step; it bundled and ran (`importProbe: true`). Importing `../../convex` was not tried.
- **Local world warning:** the local Workflow world logs that `POST /.well-known/workflow/v1/flow` is unauthenticated; fine for local dev, never expose `eve dev` beyond loopback.
- **Child models:** the parent stream shows only parent `model.started`; child events (including `anthropic/claude-haiku-5.5`) are on the child's own stream (`child.opened.sessionId`).
